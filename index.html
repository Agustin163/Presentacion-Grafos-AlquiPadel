El Problema de Negocio: El "Falta Uno"

La dificultad de completar parridos abiertos mediante publicaciones generales y búsquedas tradicionales.

Problemática Operativa Actual

La Grilla Abierta Indiscriminada

En deportes de equipo, la principal barrera es completar el turno a último momento. Publicar el partido abierto en una grilla general expone el encuentro a desajustes críticos:

  • Inscripción de jugadores de distinta categoría o género.
  • Usuarios de otra localidad o con bloqueos previos (conflictos).
  • Spam masivo de notificaciones a toda la base de usuarios.
¿Por qué no alcanza una consulta SQL?

Una consulta tradicional evalúa datos estáticos fríos, pero desconoce la topología social: no sabe con quién prefiere jugar el organizador ni pondera su historial real en cancha.

ENFOQUE DESCARTADO SELECT * FROM jugadores WHERE localidad = 'Pila' AND genero = 'M';
✕ Ignora vínculos de 2° grado, afinidad histórica y rechazos.
NUESTRO OBJETIVO: MOTOR EN MEMORIA

Recomendación Inteligente Basada en Grafos

Construir un motor dinámico en memoria RAM que explore la red real de jugadores a partir del creador del partido, garantizando precisión deportiva y cero spam.

1. Afinidad Social
Priorizar jugadores que tienen relaciones previas con el organizador de su entorno.
2. Muros Estrictos
Corte inmediato por Género, Localidad y estado "No Deseado".
3. Cercanía Social
Recorrido por niveles (Contactos directos ➔ Amigos de amigos).
4. Envios Dosificados
Limitar la cantidad de invitaciones para evitar notificaciones masivas..

Esquema Relacional de Datos (Persistencia SQL)

La Bases de Datos almacena los jugadores, el historial deportivo y las relaciones que permiten construir el grafo.

1. Jugadores NODOS
PKid_jugador INT
nombre VARCHAR(80)
genero CHAR(1)
localidad VARCHAR(60)
Almacena los atributos estáticos requeridos para evaluar los filtros estrictos.
2. Partidos_Históricos PESO BASE
FKid_jugador_a INT
FKid_jugador_b INT
cantidad_partidos INT (+1 auto)
Crecimiento orgánico y pasivo. Registra cuántas veces compartieron cancha dos jugadores.
3. Relaciones BONO / PODA
FKid_origen INT
FKid_destino INT
estado TINYINT (1 | 2)
Acción manual: 1 = Favorito (+50 pts) | 2 = No Deseado (Cortocircuito).

// CargadorGrafo.java

public class CargadorGrafo {

    /**
     * Propósito: pasar los datos de SQL a la RAM.
     * Precondición: db abierta y grafo vacío.
     * Poscondición: el grafo contiene todos los jugadores y sus conexiones.
     */
    public static void cargar(Connection db, GrafoAlquiPadel grafo) throws SQLException {

        // PASO 1: nodos -> catálogo
        PreparedStatement psNodos = db.prepareStatement(
            "SELECT id_jugador, nombre, genero, localidad FROM Jugadores");
        ResultSet rsNodos = psNodos.executeQuery();

        while (rsNodos.next()) {
            grafo.agregarJugador(new Jugador(
                rsNodos.getInt("id_jugador"),
                rsNodos.getString("nombre"),
                rsNodos.getString("localidad"),
                rsNodos.getString("genero")));
        }

        // PASO 2: historial + relaciones -> aristas con peso
        PreparedStatement psAristas = db.prepareStatement(
            "SELECT ph.id_jugador_a, ph.id_jugador_b, ph.cantidad_partidos, r.estado " +
            "FROM Partidos_Historicos ph " +
            "LEFT JOIN Relaciones r " +
            "ON ph.id_jugador_a = r.id_origen AND ph.id_jugador_b = r.id_destino");
        ResultSet rsAristas = psAristas.executeQuery();

        while (rsAristas.next()) {
            int estado = rsAristas.getInt("estado");   // NULL en SQL -> getInt devuelve 0 (Neutral)

            int peso = rsAristas.getInt("cantidad_partidos") + (estado == 1 ? 50 : 0);

            grafo.agregarConexion(rsAristas.getInt("id_jugador_a"),
                                  rsAristas.getInt("id_jugador_b"), peso, estado);
        }
    }
}
GrafoAlquiPadel.java — Motor de Búsqueda y Filtrado Paso 3 de 4 

// GrafoAlquiPadel.java - Motor de Exploración BFS y Poda

public class GrafoAlquiPadel {
    Map<Integer, Jugador> catalogo = new HashMap<>();        
    Map<Integer, List<Arista>> adyacencia = new HashMap<>();

    public void agregarJugador(Jugador j) {
        catalogo.put(j.id, j);
        adyacencia.put(j.id, new ArrayList<>());
}
    public void agregarConexion(int a, int b, int peso, int estado) {
        adyacencia.get(a).add(new Arista(b, peso, estado));
        adyacencia.get(b).add(new Arista(a, peso, estado)); // Grafo No Dirigido
    }

    public void buscarCandidatosBFS(
    int idCreador,
    String locPartido,
    String genReq,
    int nivelMax,
    int limiteCandidatos,
    ArbolBST arbol) {

    Map niveles = new HashMap<>();
    Cola cola = new Cola<>();

    niveles.put(idCreador, 0);
    cola.encolar(idCreador);

    int candidatosNivel1 = 0;

    while (!cola.estaVacia()) {

        int actual = cola.desencolar();
        int nivelActual = niveles.get(actual);

        // Limite de exploracion
        if (nivelActual >= nivelMax) break;

        // Si los contactos directos son suficientes,
        // no exploramos sus conexiones.
        if (nivelActual == 1 &&
            candidatosNivel1 >= limiteCandidatos) {
            continue;
        }

        // Recorremos las conexiones
        for (Arista conexion : adyacencia.get(actual)) {

            if (conexion.estado == 2 ||
                niveles.containsKey(conexion.destino)) {
                continue;
            }

            Jugador vecino = catalogo.get(conexion.destino);

            if (vecino == null) continue;

            niveles.put(conexion.destino, nivelActual + 1);

            // FILTROS ESTRICTOS
            if (!vecino.localidad.equals(locPartido) ||
                !vecino.genero.equals(genReq)) {
                continue;
            }

            // CALCULO DEL PESO FINAL
            int nivelDestino = nivelActual + 1;

            int pesoDefinitivo =
                (1000 / nivelDestino) + conexion.peso;

            // INGRESO AL BST
            arbol.insertar(vecino, pesoDefinitivo);

            if (nivelDestino == 1) {
                candidatosNivel1++;
            }

            cola.encolar(conexion.destino);
        }
    }
}
    }
ArbolBST.java — Ordenamiento Dinámico y Regla de Negocio Paso 4 de 4 


public class ArbolBST {

    static class Nodo {
        Jugador jugador;
        int peso;
        Nodo izquierda;
        Nodo derecha;

        Nodo(Jugador jugador, int peso) {
            this.jugador = jugador;
            this.peso = peso;
        }
    }

    Nodo raiz;

    // Inserta un jugador en el árbol
    public void insertar(Jugador jugador, int peso) {
        raiz = insertarRec(raiz, jugador, peso);
    }

    // Menores o iguales a la izquierda, mayores a la derecha
    private Nodo insertarRec(Nodo actual, Jugador jugador, int peso) {

        if (actual == null) {
            return new Nodo(jugador, peso);
        }

        if (peso <= actual.peso) {
            actual.izquierda = insertarRec(
                actual.izquierda, jugador, peso
            );
        } else {
            actual.derecha = insertarRec(
                actual.derecha, jugador, peso
            );
        }

        return actual;
    }

    // Inicia el recorrido desde la raíz
    public void inOrderInverso(Cola colaDespacho) {
        inOrderInverso(raiz, colaDespacho);
    }

    // Recorre de mayor a menor puntuación
    // Derecha -> Raíz -> Izquierda
    private void inOrderInverso(
        Nodo actual,
        Cola colaDespacho) {

        if (actual == null) {
            return;
        }

        inOrderInverso(actual.derecha, colaDespacho);

        colaDespacho.encolar(actual.jugador);

        inOrderInverso(actual.izquierda, colaDespacho);
    }
}

Conclusiones e Impacto de la Arquitectura

Síntesis del valor técnico y operativo alcanzado con el motor de recomendación de AlquiPadel.

Eficiencia en Servidor

1. Optimización de Recursos

La base de datos se mantiene pasiva almacenando hechos históricos simples, mientras que la memoria RAM instancia únicamente grafos dispersos acotados mediante Listas de Adyacencia, liberando recursos al finalizar cada tanda.

Búsqueda inteligente

2. BFS y filtros de compatibilidad

Permiten explorar la red por niveles, descartar jugadores incompatibles y evitar expansiones innecesarias cuando ya se alcanzó el límite de candidatos.

Priorización y despacho

3. BST y cola FIFO

La sinergia entre BFS (proximidad social por niveles) y un Árbol BST con In-Order Inverso (inserción y ordenamiento dinámico en $O(\log n)$) resuelve el "Falta Uno", maximizando la ocupación de canchas y la rentabilidad de AlquiPadel.

BFS + BST O(log n) ➔ +Rentabilidad
